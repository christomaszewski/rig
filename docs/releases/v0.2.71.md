Replay pulls missing native images before image-dependent validation, selects recorded ROS requests for started service servers, and suppresses bag outputs only when recorded publisher evidence accounts for their replacement.

- Resolve the active image set from the exact replay configuration, validate capabilities, and pin launch to immutable image IDs. Support `--pull missing|always|never`; checks and previews never pull.
- Inspect recorded request contents, selected origin, and replay window with bounded, read-only helpers and validated cache evidence.
- Keep unknown/shared topics eligible and report topic/service selection reasons. Respect explicit opt-out and scripted-call precedence.
- Detect actual player/injector completion, stop startup after a failed prerequisite, preserve failure evidence, and avoid repeated hashing of unchanged shared artifacts.
- Preserve fractional replay boundaries and use an exclusive end timestamp through the compatible player.
- Gate releases on native amd64/arm64 Docker acquisition tests and verify installed wheel contents.

### Upgrade requirements

Update Rig and the selected service launch surfaces together: rig-infra 1.18.0, camera-service 1.11.0, and the updated dashboard launcher. Explicitly started SBG/Ouster services require their new launcher releases; local Doodle/NovAtel routes also need the new contract. Existing vendored services require `rig swap` or package upgrade; `replay prepare --player` only adds a missing player.

Rebuild/publish the deployment's `fleet-ros` and messages overlay after updating service packages. The player image must advertise `io.rig.rosbag2.replay=1`; a launcher upgrade alone cannot update old image bytes. Use the normal `rig build --no-cache` workflow with a fresh tag, then refresh catalog/bundled artifacts as applicable.

An omitted recipe `playback.services` now enables automatic recorded-call selection. Set `playback.services: []` to keep recorded calls disabled. MAVLink router remains outside this release scope and must be omitted from replay when installed.

Validation includes the full Rig suite, native Docker acquisition on amd64/arm64, native ROS playback and request tests in both infra image architectures, and an isolated installed-wheel/released-infra/published-image replay. The end-to-end run verified two automatic service requests, output suppression, exclusive bounds, capture/sealing, cleanup, and unchanged source data. Full vehicle acceptance and coordinated startup readiness remain follow-up work.

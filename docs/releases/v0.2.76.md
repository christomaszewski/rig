Cross-distro simulators and adopted images, from the Isaac-in-the-loop feedback.

- **A simulator on another ROS distro.** `simulation.ros` declares the simulator's own ROS
  settings (the probe runs in that environment). Its middleware and domain must still match the
  deployment, but its distro may now differ, for example Isaac on Jazzy against a Lyrical
  deployment. Type names alone cannot show the two sides agree, so such a session requires
  every bound topic's REP-2016 type hash to match across its endpoints. The check after startup
  decides it: it waits up to `timeout_s` for the deployment's side of each bound topic, a
  mismatch rolls the session back, and a topic still one-sided is named in a warning rather
  than passed silently.
  Humble and older report no type hashes and cannot be mixed with another distro. The probe now
  records each endpoint's hash and flags endpoints that disagree on any session, since such
  endpoints never match even on one distro.
- **`rig image adopt <registry>/<image>:<tag>`.** Replay refuses an image without a build-catalog
  row, such as a tag built and pushed by hand. Adopt records one from the registry's own
  manifest (digest, architectures and per-architecture children), replacing any rows for that
  image and tag. The row is marked `adopted` with no source revision and never copies another
  row's provenance; `--like <catalog key>` takes only the service and runtime from a row.
  `rig image audit` warns about adopted rows, and `rig bake` refuses a catalog with one unless
  `--allow-local`. A later `rig build` of the tag replaces it.
- **Tab completion for the commands the docs use.** Completion offered only the grouped forms
  (`rig image build`, `rig artifact bake`, `rig run replay`), so `rig bu<TAB>` completed nothing.
  It now also offers `build`, `bake`, `unbake`, `replay`, `runs`, `rigify` and `vendor`. Legacy
  hyphenated spellings such as `new-run` and `image-audit` still parse but are not suggested.

### Validation

- The full suite (91 scripts, 1,334 cases) passes on Python 3.9, 3.12 and 3.14. Every new test
  fails against v0.2.75.
- The probe ran against real rclpy endpoints in a Lyrical container (Fast DDS): endpoints carry
  `RIHS01_…` type hashes, a strict check passes on matching ones, and the after-startup wait
  returns as soon as both sides appear (about 1.3 s) or warns at the timeout when one side never
  does. The bundled real-ROS smoke test also passes there. A real Jazzy Isaac against a Lyrical
  deployment over `rmw_zenoh` has not been run.
- `rig image adopt`'s manifest reads were confirmed against Docker Hub with Buildx 0.38.1; the
  adopt flow itself was tested with a mocked registry.

Recorded vehicle runs can be replayed from a shipped Rig artifact, with optional offline images and opt-in coordinated startup.

- `rig bake --include-replay` adds and configures a disabled bag player when one is missing. Use `--replay-player PATH_OR_PINNED_REF` to choose its source. The source deployment is unchanged.
- Run replay directly through the artifact's `./rig replay RUN`. Add `--bundle-images` when baking to include replay-only images; load them with `./run.sh load` and replay with `--pull never` for offline operation.
- Select `--startup coordinated` to hold the bag player and camera producers until recorded consumer endpoints are ready, then commit one shared release time. Legacy startup remains the default, including for baked artifacts.
- Fail before release on readiness timeout, producer failure, cancellation or conflicting deployment ownership. Preserve failure evidence and unrelated containers.
- Gracefully stop owned containers before sealing a successful coordinated run; a failed drain leaves the run unsealed for diagnosis.
- Fix camera preview duplication and an intermittent fragment-reader race in the compatible camera release. Preserve exact frame bytes and recorded timestamps across replay fragments.
- Gate releases on native ARM64/AMD64 image acquisition and coordinated baked-artifact acceptance, with immutable companion source pins.

### Compatible packages and images

Coordinated startup requires **rig-infra 1.19.0** for the selected bag player and **camera-service 1.12.0** for recorded camera producers. Update their vendored packages and rebuild the deployment's base/messages and camera images. Both the launch surface and active producer image must support coordination; upgrading a launcher alone cannot update old image bytes.

```sh
rig swap ros2-bag-player public/ros2-bag-player@1.19.0
rig swap camera-service public/camera-service@1.12.0
```

Only update a package used by the deployment. Ordinary consumers need no new coordination API, and there is no fleet-wide service migration for this opt-in feature. Deployments upgrading from before Rig 0.2.71 must also follow that release's existing replay-contract migration requirements.

The public registry distributes service source packages. Build and publish runtime images through the deployment's normal `rig build --registry REGISTRY --tag TAG` workflow, then bake a fresh artifact. Existing artifacts retain their packaged code and images.

### Validation

All 79 Rig host suites and 21 infra host suites passed. Native base and message-overlay replay passed on ARM64 and AMD64. Camera passed 599 tests on modern ARM64, modern AMD64 and the legacy runtime, plus 300 repeated mixed-codec replays. Acceptance covered camera/bag coordination, time-zero calls, fractional windows, wall-clock playback, failure injection, legacy startup and packaging.

On the vehicle, fresh registry and offline artifacts replayed an actual recording through `./rig`: all 1,504 observed messages matched serialized payloads, all 21 source files were unchanged, and output runs finalized cleanly. Separate generated camera/bag recordings verified 125 exact frames without early or duplicate delivery. This validates the isolated replay deployment, not every vehicle application or hardware configuration.

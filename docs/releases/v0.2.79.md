Replay can now select multiple bag-logger sessions together and choose original recordings or
immutable proxies independently for each replay input.

- `inputs` recipe selectors and repeatable `--input TARGET=original|profile:NAME|proxy:ID`
  work across bags and recording-capable instances. Explicit choices need no `--use-proxies`.
  Cameras can use different profiles or retain their original recordings independently.
- `bags: all` and logger/session subsets feed one native bag player and one clock. Original
  playback uses recorded receive time and preserves overlapping messages; no live deduplication
  is performed. Split files remain one recording session.
- `rig run export RUN --recipe NAME` builds the selected proxies offline, then
  `rig replay prepare RUN --recipe NAME` validates and pins exact artifacts for
  `rig replay --recipe NAME`. Export resolves bags first so camera selection uses the final
  timeline. Source and output checksums, transformation policy, and conversion provenance are
  retained; ambiguous artifacts require an exact ID.
- Bag profiles support arrival, middleware-send, and sensor timing with deduplication disabled,
  conservative, or aggressive. Conservative mode preserves ambiguous repeats and only removes
  supported strong identity matches. Aggressive mode explicitly permits likely equal-payload
  matches within a configured receive-time window. Payload timestamps are never rewritten.
- `playback.image_sources` selects bag or camera authority independently from the video input.
  A camera can display a video proxy while algorithms receive original-quality bag images.
  The planner validates recorded image topics and rejects conflicting active publishers.
- Service-call inspection/export, window restoration, prepared state, and run provenance
  account for the complete selected bag set. Legacy single-session plans remain supported.

### Compatibility and upgrade

With no explicit `bag`/`bags` selector, replay now selects all bag sessions in the source run.
To preserve a single-logger/latest-session selection, specify it explicitly, for example
`bag: {logger: bag_logger, session: latest}`. Legacy `--use-proxies` and `proxies` recipe
preferences remain supported; contradictory old/new declarations are rejected.

Multi-input playback and bag export require rig-infra **v1.20.0**. Rebuild the `fleet-ros`
base and dependent messages overlay/runtime images to obtain the verified
`io.rig.rosbag2.multi_input=1` capability. Installing only the new launcher does not upgrade
an existing image. Original session indexes must be valid before offline bag export.

Future providers can use the same selector model; this release supports whole `bags` and
`instance:NAME` targets. Unsupported sub-input targets fail explicitly.

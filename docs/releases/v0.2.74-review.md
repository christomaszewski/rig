# v0.2.74 pre-release review

Review date: 2026-10-29. Six independent read-only reviews covered every `rig_cli` module: the
changes since v0.2.73, the package/registry layer, images/bake/artifacts, run/replay/sessions,
core/CLI, and the operator documentation. Most findings were reproduced in hermetic scripts
(temporary `RIG_HOME`, no Docker state changes). This record lists what v0.2.74 fixes and what
it knowingly defers. Severity is the reviewer's, confirmed or adjusted on verification.

## Fixed in v0.2.74

Each fix has a regression test.

| Area | Finding | Fix |
| --- | --- | --- |
| Install (new) | A crafted `source.rev` (e.g. `/../../../..`) made a failed checkout's cleanup delete `RIG_HOME`'s parent | `rev` must be a full commit id; cleanup removes only a directory it created |
| Replay | `--auto-end` never saw completion on Python < 3.11: Docker's nanosecond timestamps failed `fromisoformat` | Fractions normalized to 6 digits |
| Runs | Labels matched by suffix: a second `rig replay flight1` resolved to the previous replay's output run | Labels match exactly (plus the same-second `-N` suffix); also in `rig catalog` and `fleet sync` |
| Reconstruct | Artifact extraction honored `../` member paths | Shared `safe_extract` (data filter, or the same checks by hand on older Pythons); `unbake` uses it too |
| Manifest | Instance names were unchecked: `../../vehicle` rendered over `vehicle.yaml`; uppercase or dotted names broke compose | Names must match `[a-z0-9][a-z0-9_-]*` |
| Vendor | `launch_surface: [../x]` wrote outside `services/<svc>` | Entries must stay inside the service directory |
| Fleet | `fleet up --var` keys reached a remote shell unvalidated (`;` ran) | Keys must be lowercase names, as in `provision --var` |
| Replay prepare | A failed BACKUP during `--player` wiring triggered a restore that deleted live files | Restore only after every backup completed; keep the backup if restoring fails |
| Data dir | Migrating into another registry merged it (rsync) or deleted it (no rsync) | Only an interrupted copy of the same registry may be resumed |
| Run archive | A run manifest's `vehicle: ../..` placed the archive outside `--to` | `vehicle` must be one path component |
| Cleanup | `rig cleanup <names>` also removed other instances' images | Selection removes only its own images, never one a kept instance runs |
| Doctor | A disabled alternative row on the same host port blocked `rig up` | Only enabled rows clash (WARN otherwise); string ports compared too |
| Status | One missing launcher aborted `rig status` and `run end` | Reported as that row's "no launcher" |
| Manifest | `ros.domain_id` templated or out of 0..232 crashed or was exported | Refused with a clear message |
| Install | Rollback restored files without their mode (non-executable launchers) | Modes are snapshotted and restored |
| Build (new) | Matrix retry hint missed cancelled tasks and mirror-only services; verified images of a failed run never reached the catalog | Hint names everything not done; verified images are cataloged, `last_build` untouched |
| Mirrors (new) | Upstream branch rename wedged a mirror; concurrent rig processes failed on ref locks; stale `.gitmodules` entries and `update = none` broke checkouts; relative local URLs resolved against the mirror | `--prune` on fetch, lock retry, skip non-gitlinks like git, absolute local URLs |
| Mirrors (new) | `--offline` hint shown when no mirror existed | Hint only for an existing mirror, with its last successful fetch |
| Init (new) | Rollback in an existing directory kept init's overwritten README/.gitignore | Overwritten files are restored and created paths removed |
| Build (new) | Offline check ignored the legacy `<service>-<rev>` source cache | Both layouts accepted |
| Tests | Eight test scripts failed on Python 3.9 (the deb's declared minimum) | Test-only fixes; the suite now passes on 3.9 and 3.12 |
| Lock (high) | `--locked` kept one registry commit, moved by every later install, upgrade, save and overlay apply: a historical `@version` install, a later install, or a required service's major bump made `--locked` fail | Each lock row records the commit its bytes came from; `--locked` resolves every package (and a profile's required service, before its constraint is checked) at its own row's commit, then by its locked version from history, then the registry commit for older locks |
| Lock (high) | `--locked` suite installs never checked overlay or vehicle-plan payload hashes | Overlays apply in locked mode and the plan's hash is checked before anything is written |
| Upgrade (high) | `pkg upgrade` moved a shared service past a profile's `requires.service` | The service moves only as far as every profile requiring it accepts; otherwise its pin is kept, or an exact requirement is served from history |
| Upgrade (high) | Versions compared by equality: a save published on an unmerged branch was "upgraded" back to the older registry version, dropping the tuning | No pin moves to an older version; `pkg list` says "registry carries older X" instead of offering it |
| Save (high) | `pkg save` from an out-of-date pin published over a newer version, undoing its changes | Save and auto-bump promote refuse when a newer version changed keys the publish would undo, and point at `pkg upgrade` |
| Fleet (high) | A user-level `data_dir` outranked SIL rows' simulated machine tier, merging every simulated vehicle into one run registry | SIL rows run as simulated machines (`RIG_SIMULATED_MACHINE`), which have no user tier |
| History | Every `--locked` install left a `rig-history-*` temp directory behind | Removed when rig exits |

## Deferred (known issues)

These pre-date v0.2.74. No high-severity issue remains open.

### Medium

- Registry alias ≠ namespace breaks suite/profile installs (`install.py` `resolve_ref`).
- Three-way merge misses prefix/type-change conflicts (`workingcopy.py`, `promote.py` rebase).
- Un-saving a non-last overlay changes the render (`save.py`); a second yank restores the yanked
  version (`history.py`); multi-name `pkg remove` failing midway leaves tree and lock apart.
- Registry payload paths (`config.payload`, vehicle payload, example `name:`) are not confined.
- Vars with list/dict values are not interpolated; chained vars on a missing identity give a
  misleading error that blocks lazy commands (`interpolate.py`, `manifest.py`).
- `fleet status` reports any remote failure as "needs rig ≥ 0.1.66" (`fleet.py`).
- False `config_dirty_at_seal` after session/sim teardown and replay rotation (`runs.py`,
  `session_runtime.py`); a later plain `rig up` can join a still-open replay run;
  `--auto-end` holds the session lock for the whole playback.
- `reconstruct --config` on runs whose rows bind overlays cannot render (`reconstruct.py`).
- `unbake` into a non-empty directory keeps stale files and may return the wrong tree.
- Re-baking a bundled artifact offline on the vehicle cannot find the bundled images.
- Registry-mode bake pins never check the target architecture; the local-build guard skips
  images whose digest did not resolve.
- Replay with camera recordings ignores the bag player's `play.rate`: camera-service paces its own
  replay `speed`, so faster-than-realtime replays desynchronize cameras and bags.

### Low

- Outside a deployment, rig falls back to its own directory's sample `vehicle.yaml`.
- `--offline` checks sources for out-of-scope or replaced-base services (fails safe).
- Shell completion mishandles quoted words; `rigify` accepts digit-leading or `../` names.
- Docker daemon errors are reported as "requires Docker API 1.48"; unreachable registries cost one
  timeout per stack sharing an image; the launcher `config` call has no timeout in bake.
- `rig artifact list` decompresses whole bundle archives; an in-place export shares a hardlinked
  manifest with its source run; `bake_fleet` raises a raw KeyError for an unrouted service.
- `prepare`'s printed "Replay with:" command drops selection flags; a `--to` past the bag end drops
  the final message; a corrupt run manifest is rewritten on every `up`.
- Versions published by `pkg save`/`promote` record no per-row commit: `--locked` finds them by
  version in the registry's history once merged, but not while they sit on an unmerged
  `promote/*` branch.
- Registry re-add with a new URL keeps syncing the old clone; save/adopt leaves a stale lock row.
- Refs: `ref: HEAD` fails against a bare mirror; unquoted YAML refs like `1.10` become `1.1`.

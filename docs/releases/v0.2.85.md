`rig sim` can attach a deployment to a simulator other than Isaac and record which simulator
it was. A session torn down with `--end-run` is no longer sealed as if its configuration had
been edited.

### Simulation

- New experimental `simulation.provider: external`. The recipe names the simulator with
  `simulator: {name, version}`, both non-empty strings. Rig attaches as it does to Isaac: it
  checks the ROS settings, the selected tiers, one authority per output, the runtime images,
  the bound endpoints with their type hashes and QoS, and one advancing `/clock`. It does not
  launch, reset, step or seed the simulator.
- The plan, the run's `simulation` metadata, the saved session and the run's
  `.rig/simulation/` directory say `provider: external`, carry the `simulator` mapping, and
  give `clock` as `external`. The scene, the seed and the simulator's name and version are
  recorded as the recipe states them. Rig does not verify them.
- Recipes stay strict. `simulator` is refused with `isaac`, `isaac_version` is refused with
  `external`, and any other provider is refused as before.
- Messages name the simulator by its stated name. The Humble/Jazzy warning concerns Isaac's
  tested distributions and is raised for `isaac` only.
- Isaac recipes and saved Isaac sessions are unchanged: no new key in the plan, the metadata
  or the saved state, and the same messages.
- [examples/external-attach](https://github.com/christomaszewski/rig/blob/v0.2.85/examples/external-attach/README.md)
  has a recipe to copy. The reference describes two arrangements for a single host: a second
  Zenoh router for the simulator, which the deployment's router connects to, and a probe run
  in a ROS image through `simulation.probe` on a host without ROS.

### Sessions

- `rig sim down --end-run`, and `rig down --end-run` on a recipe session, marked every run
  `config_dirty_at_seal` and warned that the config had changed after the last `up`, whether
  or not anything had. The teardown compared the run's snapshot with a manifest rebuilt from
  the saved session, which holds no vars. Sealing now reads the deployment's own vars and
  env. A deployment edited after `up` is still reported.

### Upgrade

Only the Rig CLI changes; no rig-infra release or service image rebuild is required. Existing
recipes need no change. A run sealed by an earlier version keeps the flag it was given.

```sh
rig sim check --recipe world
rig sim up --recipe world --label world-a
rig sim down --end-run
```

### Validation

All 100 local test modules pass. Three are new: `tests/test_sim_external.py` (29 cases),
`tests/test_sim_external_replace.py` (3) and `tests/test_session_seal.py` (2). No existing
test file changed. Four of the 29 pin an Isaac session's plan, metadata, saved state and
wording as v0.2.84 writes them, and one of the session cases fails on v0.2.84.

The provider was exercised live on 2026-11-12 against one mission-level simulator on one
amd64 host (Lyrical, `rmw_zenoh_cpp`): `rig sim check`, `rig sim up` and
`rig sim down --end-run` over several sessions, and `rig replay --recipe` of a recorded run
under the shared recipe, with the probe run in a container. An untouched session sealed
without the flag. Not exercised: a simulator on another host or another ROS distribution, a
DDS middleware, sensor replacement, and a failed startup with its rollback. Live Isaac
acceptance is still pending and is not changed by this release. The release workflow also
requires the full Linux test suite before publishing packages.

See [an external simulator](https://github.com/christomaszewski/rig/blob/v0.2.85/docs/SIMULATION.md#an-external-simulator).

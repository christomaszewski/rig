Build and bench-identity fixes from the Isaac-in-the-loop feedback.

- **Targeted builds over a single-platform tag.** `rig build --arch`/`--platform` now reads the
  architecture of a single-platform tag (a plain `docker push`), so rebuilding that architecture
  over it is allowed. Before, rig saw no architectures and refused. When a targeted build would
  drop architectures, the refusal names the ones the registry tag serves and the ones the build
  writes.
- **The ROS domain on a bench.** A vehicle-local `ros: {domain_id: N}` (a tree's
  `vehicle.local.yaml` or the machine file; nothing else under `ros`) sets the domain above
  vehicle.yaml's explicit `ros.domain_id`. `rig doctor` names where the domain came from. A bench
  tree whose own `vehicle.local.yaml` sets a numeric `vehicle_id` that differs from vehicle.yaml's
  explicit domain still joins that domain; `rig doctor` and `rig up` now warn about it. Setting
  the bench's own `ros.domain_id` (even to the same number) silences the warning.
- **DNS in managed Buildx builders.** BuildKit cannot hand a loopback DNS stub (systemd-resolved's
  `127.0.0.53`) to RUN steps and falls back to `8.8.8.8`, so on networks that block public DNS
  every fetch stalled and failed while `docker build` worked. When the Docker daemon is this
  host's and `/etc/resolv.conf` names only a loopback stub, rig's managed builder gets the upstream
  servers from `/run/systemd/resolve/resolv.conf`. `RIG_BUILDKITD_CONFIG` names a
  `buildkitd.toml` snippet to add; a `[dns]` table in it replaces the automatic one. These settings
  never rename the builder: when they change (a new network), rig re-creates it under the same
  name with `docker buildx rm --keep-state`, so the build cache that offline builds rely on
  survives. A build step that fails on name resolution now ends with a hint saying so.

### Validation

- The full suite (91 scripts, 1,323 cases) passes on Python 3.9, 3.12 and 3.14. Every new test
  fails against v0.2.74.
- The image-config read behind the single-platform check was confirmed against Docker Hub with
  Buildx 0.38.1. The DNS fix was tested with mocked Docker and resolv.conf files and has not yet
  been exercised on a split-DNS Ubuntu host.

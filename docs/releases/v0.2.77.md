Local GitHub/GitLab checkouts used as registries now say when a pin cannot be reproduced.

- **Lock rows record commits from local checkouts.** A `local-dir` registry that is a git
  checkout (`rig registry add NAME --path <checkout>`) recorded no commit in `rig.lock`, so
  `--locked` could only look packages up by version. Each row now records the last commit that
  touched the package, and the registry row records the checkout's HEAD.
- **Installs warn about bytes no one else can fetch.** Installing a package whose files have
  uncommitted changes in the checkout warns that the lock pins bytes no commit holds (and records
  no commit for it). Installing one from a commit that is on no remote branch, as of the last
  fetch, warns that other machines cannot reproduce it until you push. A plain folder that is not
  a git checkout stays silent.
- **A local clone source is stored absolutely.** `rig registry add NAME <path>` (a git registry
  cloned from a local checkout) stored the path as typed, so a relative path broke `rig registry
  sync` from any other directory. It is now stored absolutely and must be a repository's root (a
  work tree's top level, or a bare repository); a folder that is not a git repository points at
  `--path`.
- **Sync and list show a checkout's git state.** For a `local-dir` git checkout, `rig registry
  sync` and `rig registry list` show its branch, unpushed commits, how far it is behind its
  upstream and its uncommitted changes, read without fetching. Rig still never pulls a folder it
  uses in place.

A registry folder counts as a git checkout only when its `registry.yaml` is tracked, so a plain
folder inside an unrelated repository (a home directory kept in git) is never treated as one.

### Validation

- The full suite (91 scripts, 1,339 cases) passes on Python 3.9, 3.12 and 3.14. Every new test
  except the plain-folder guard fails against v0.2.76.
- A scripted trial with a real checkout and bare upstream covered a clean install (commits
  recorded), an uncommitted edit (warned, no commit), an unpushed version (warned, commit recorded,
  not reproducible from the upstream) and a relative clone source (absolute; sync from another
  directory works).

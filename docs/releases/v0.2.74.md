Offline and selected-service builds, registry services in `rig init`, and fixes from a full
pre-release review.

- **Build only some services.** `rig build SERVICE...` (service or instance names) builds just
  those; the others keep their registry images. A named consumer builds from the published base;
  naming the base provider rebuilds the base and its msgs overlay. After a failure, rig prints the
  `rig build` command that retries only what failed or never ran.
- **Build without the network.** Every git source a build needs — `rig.lock` service pins, msgs
  overlay `source:` repos, and the new rigging key `build.sources` — resolves through one bare
  mirror per repo in `$RIG_HOME/cache/git`. `rig src sync` fills them; `rig build --offline`
  fetches nothing, never pulls, checks every source and mirrored image first, and builds from the
  build cache. `--offline --check` reports without building. Builds receive their sources as
  `RIG_BUILD_SOURCES` (`--build-context <name>=$RIG_BUILD_SOURCES/<name>`).
- **Local-checkout builds cannot ship silently.** Images labelled `io.rig.build.local` (rig-infra's
  `FLEET_MSGS_LOCAL` overlays) draw an `rig image audit` warning, and `rig bake` refuses them
  without `--allow-local`.
- **`rig init` from a registry.** `--infra public/zenoh-router` and a new repeatable `--add`
  (anything `rig add` takes) install while scaffolding; registry refs are checked before any
  write and a failed install rolls the target back.
- **Package reproduction and upgrades.** Each `rig.lock` row records the registry commit its
  bytes came from, and `--locked` reproduces every package from its own row — after historical
  installs, later installs, or a required service's major bump — and now checks suite overlay
  and vehicle-plan hashes. `pkg upgrade` keeps a shared service within every profile's
  `requires.service` and never moves a pin to an older version. `pkg save` refuses to publish
  from a pin when a newer version changed keys it would undo.
- **SIL fleets.** A user-level `data_dir` (`rig setup --data-dir`) no longer merges every
  simulated vehicle into one run registry.
- **Fixes.** `--auto-end` now works on Python < 3.11 (JetPack 6); run labels resolve exactly (a
  repeat `rig replay X` no longer picks the previous replay's output); archives extract safely;
  instance names are validated; `launch_surface` paths, `run archive` destinations and
  `fleet up --var` keys are confined; `replay prepare`, registry migration and `rig cleanup <names>`
  no longer delete data they should keep; doctor no longer blocks `up` on a disabled row's port;
  and more — see the [pre-release review](https://github.com/christomaszewski/rig/blob/v0.2.74/docs/releases/v0.2.74-review.md), which also lists the known issues
  this release defers.

Requires rig-infra with `RIG_BUILD_SOURCES` support for msgs overlays to build from rig's mirrors;
older rig-infra keeps cloning in the builder.

### Validation

- The full suite (91 scripts, 1,313 cases) passes on Python 3.12 and on Python 3.9, the deb's
  declared minimum. Branch coverage of `rig_cli` is 87%; the new modules are at 88–96%
  (`gitmirror` 88%, `build_sources` 96%, `build` 96%, `matrix_build` 85%).
- On the real deployment, `rig src sync` and `rig build --offline --check` passed, and the msgs
  overlay compiled from rig's mirror export without a clone. On a disconnected builder warmed by
  one online build (with `# syntax=` removed from a copy of the Dockerfile), the overlay rebuilt
  from a `FLEET_MSGS_LOCAL` checkout and pushed to the internal registry. Section 9 B of the
  [offline builds plan](https://github.com/christomaszewski/rig/blob/v0.2.74/docs/offline-builds-plan.md)
  has the details.
- Run locally, not in hosted CI.

### Known issues

Camera replay does not follow the bag player's `play.rate`. Medium and low issues found by the
review that pre-date this release are listed in the
[review](https://github.com/christomaszewski/rig/blob/v0.2.74/docs/releases/v0.2.74-review.md).
